# Working on Bookshelf

This is the standalone frontend companion to `bookshelf-api`. Keep domain content limited to books and authors. Use public packages and docs. No private registries, credentials, cloud SDKs, analytics, authentication, or remote error reporting. Do not add ESLint, Prettier, Redux, Sass, or CI deployment configuration.

## Commands

Use Node 22 (`nvm use`), `npm ci`, then `npm run dev` against the local backend. Default frontend port is 5173; override `PORT`. The server-only backend origin comes from `BOOKSHELF_API_URL`. Scripts load `.env`. Astro 7 manages the dev server in the background; stop it with `npx astro dev stop`.

Before delivering changes, run the relevant tests plus `npm run lint` and `npm run build`. UI changes should run `npm run test:stories`; integrated workflows should run `npm run test:e2e` against local services. Keep tests’ unique record creation and `finally` cleanup, never clear the user’s database. Run `npm run format` for Biome formatting.

## Boundaries

- `src/api/client.ts`: one JSON client, request IDs, status-aware `ApiError` normalization. Do not add fetch calls inside UI components.
- `src/api/queries/books.api.ts`: endpoint requests; `books.queries.ts`: query keys/hooks; `books.mutations.ts`: mutations, invalidation, success toasts. TanStack Query owns server state; no automatic mutation retries.
- `src/server/`: fixed-origin SSR proxy and environment configuration. Preserve response status and request IDs, including 503 and 504. Do not expose the upstream URL as a browser environment variable.
- `src/stores/`: Nanostores for client state only. Books stores are per island to avoid shared SSR state; URL state is shareable and supports history navigation. Theme persists in local storage; initial React markup must hydrate consistently regardless of persisted theme.
- `src/types/schema.ts` and `api/swagger.json`: generated by `npm run types:generate` from the running backend. Put application aliases in `src/types/api.ts`, never hand-edit the generated schema.
- `src/components/features/`: books, authors, rollup, health. Each root island has its own QueryClient and error boundary.
- `src/mocks/`: shared MSW fixtures/handlers for tests and Storybook only.

## Add a component

The application uses React 18 and Tailwind 3. Use the shadcn CLI’s public Tailwind 3 registry to generate a base, for example:

```sh
npx shadcn@latest add https://v3.shadcn.com/r/styles/new-york/button.json
```

Keep generated bases in `src/components/ui`. Add an application-facing `BName.tsx` wrapper in `src/components/bookshelf`; include accessible labels, pending/error behavior where relevant, and a sibling `BName.stories.tsx` with `satisfies Meta<typeof BName>` and a `Bookshelf/Components/BName` title. Extend existing theme variables rather than adding unrelated palettes.

Storybook uses CSF 3, MSW 3's `mswLoader()` from `msw-storybook-addon/csf3`, and addon-vitest’s automatic preview annotations. Add shared handlers to `src/mocks/handlers.ts` and per-story overrides under `parameters.msw`. Include newly discovered browser dependencies in Storybook's Vite `optimizeDeps.include` if fresh-cache tests cause a Vite reload.

## Local integration

README documents host and Compose startup. Compose includes a sibling backend via `BOOKSHELF_API_PATH`; don't copy backend code into this repo. Preserve backend data and avoid default-port conflicts during tests. Run the app as a non-root user in Docker. Keep `.env`, build results, and browser artifacts out of Git. Audit source and lockfile for credentials, private registries, and unrelated business content before publishing.
